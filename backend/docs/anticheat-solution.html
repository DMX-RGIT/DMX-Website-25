Security Design Document

DMX Game Leaderboard
Anti-Cheat Solution

What is happening, why it happens, and how we can stop it.

1 The Problem

Our Snake game runs in the browser and the leaderboard is public. The browser calculates the score and level locally and then sends them to POST /api/v1/gamescores. The backend currently accepts those values and stores them.

This means someone does not even need to play the game. They can use cURL, Postman, Thunder Client or a Python script and simply send a fake score.

Bottom line: The browser says "I got 999999" — and the database says "okay ✓".

2 Where It Happens in the Code

  • The frontend calculates the score and level during the game.
  • The frontend sends those values in the score submission request.
  • gamescores.py creates a database object directly from the received score and level.

There is no server-side replay or gameplay verification before the values are stored.

3 CORS: Source ≠ Intent

CORS is already present in main.py. It can restrict which website origin is allowed to make browser requests — helping verify the source of a request.

But CORS cannot verify intent. It can tell us "this came from our website", but not "this score was actually earned by playing". cURL, Postman and Python scripts can call the API without touching browser CORS at all.

4 Why Encryption / HMAC Is Not Enough

Encrypting the score or adding an HMAC in the browser does not solve the root problem. The browser is still where the score is calculated, and the browser is controlled by the player.

We can authenticate the user and verify who sent the request, but that does not make the score trustworthy. Any secret shipped in client-side JavaScript can be discovered via DevTools and reproduced.

In simple words: we can catch the user, but we still cannot trust the number he sends.

5 Our Solution: "We Simply Mimic the Game"

Instead of trusting the score, we let the server mimic the same game. The server creates a game session and a deterministic seed. The client records the player's inputs and timing.

When the game ends, the server replays the game itself — same starting state, same food positions, same movement rules, same collision rules, and same scoring rules.

The client does not decide the final score. The server calculates the score from the replay and stores only that result.

6 What the Server Checks

  • Where the snake started and where the food appeared.
  • What direction was pressed and when.
  • Whether every movement was valid.
  • Whether the snake actually reached the food.
  • Whether collisions, level progression and speed changes happened correctly.
  • What score those actions actually produce.

7 The Important Part: Deterministic Food

The current game uses Math.random() for food placement. A server replay cannot reliably reproduce the exact same sequence from that random source.

We replace it with a seeded deterministic random generator. Then the server and client can produce the same food sequence from the same seed.

Same seed + same rules + same inputs = same game.

8 What About a Python Bot That Actually Plays?

A simple fake-score script is easy to stop. A more advanced Python script could actually play Snake, send valid inputs and produce a valid replay. Replay verification alone cannot prove a human was holding the keyboard.

For that case, we add a bot-detection layer — either Google reCAPTCHA or our own lightweight checks based on timing, reaction speed, game duration and suspicious input patterns.

The goal is not to mathematically prove "human". The goal is to stop simple automation and flag behaviour that looks obviously scripted.

9 Cases We Cover

Case Action
Fake cURL / Postman score Reject
Fake score + level values Reject
Fabricated input sequence Reject if replay fails
Normal human player Accept if replay is valid
Bot that actually plays Replay + bot checks
Same session submitted twice Reject
Too many submissions Rate limit

10 Why Public Ranking Games Need This

A public leaderboard gives meaning to the final number. If the browser can simply choose that number, the leaderboard is effectively asking the player to grade their own exam.

Competitive games therefore use authentication and server-authoritative game state. For our Snake game, server replay + basic anti-bot checks is a practical middle ground that covers the vast majority of abuse without requiring a full game server.
